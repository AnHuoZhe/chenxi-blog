拖入项目文件夹 → AI 分析结构 → 推荐页面架构 → 画线框图 → 填组件 → 导出 Next.js 项目。

GitHub：[AnHuoZhe/frontend-design-canvas](https://github.com/AnHuoZhe/frontend-design-canvas)

## 这解决什么问题

拿到一个项目，脑子里大概知道需要几个页面、每个页面有什么区块——但要把它变成实际代码，中间缺了一大步。Figma 是给设计师用的，v0/Lovable 是黑盒。这个工具走第三条路：AI 帮你分析推荐，但每个 Frame 都是你自己确认和调整的。

## 核心设计决策

不"一句话出页面"——AI 擅长分析（读代码、识别模式），人擅长决策（判断布局合不合理）。AI 分析四步接力（识别类型→提取页面→生成布局→用户审查），用户拿到的是可编辑的线框图。

Frame 不是组件，是"对页面空间的一种承诺"——先锁架构，再填组件，两个阶段独立进行。

AI 分析管道四步串联，每步只问一个窄问题，上一步结果只传摘要不传全文——这个设计来自 grill-me-codex 和 forge 的借鉴：不让同一个上下文既出题又阅卷。

## 为什么做桌面版

Web 版跑通了概念验证（171 测试全绿），但 IndexedDB 隐私模式丢失、浏览器标签切换丢状态、文件拖拽受沙箱限制——这三个问题是 Web 平台的结构性缺陷。桌面版用 SQLite 做持久化、单窗口单焦点、文件系统直接读写。

Web 版已完工可直接跑，Desktop 版（Electron）网络请求被 Windows 防火墙阻断，已搁置等后续排查。

## 技术栈

Next.js + React + Tailwind + SVG 画布 + ToolManager 架构。Desktop 版用 Electron + SQLite。171 个测试。
