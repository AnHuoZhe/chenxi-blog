锻造 Forge 是一套面向 Codex 和 Hermes 的 AI 辅助产品开发流程，把“边想边做”变成显性管线：需求澄清→架构设计→架构审查→任务拆解→逐模块实现→模块审查→系统审查→归档。

用户说“锻造 XX”即可启动流程。每个阶段都有输入、输出、审查标准和状态门禁，审查没有通过就不能继续推进。

## 角色分工

forge（编排器）：流程导演。读取 forge-state.json 判断阶段，写入 brief，派发子 Agent，推进状态并处理异常恢复。它不能跳过中审和大审，也不能让目标 Agent 自己宣布通过。

product-designer（设计专家）：负责需求澄清、架构设计和任务拆解。Hermes 版的需求澄清和架构设计由主对话完成，Codex 版按平台技能执行。设计结果必须落到 features.md、architecture.md 和 tasks.json。

product-reviewer（审查专家）：独立读取设计或代码，不继承设计过程中的对话上下文。负责架构审查、任务审查、模块基础审查和 Agent 系统审查。

implementer（编码专家）：按 TDD 流程实现单个任务，保存测试结果和模块决策记录。被审查打回时只修复受影响任务，不重做已经通过的部分。

用户拥有最终确认权。严格模式下逐阶段确认，简单模式下只在关键节点确认，无脑模式下自动推进非关键暂停点。

## 七阶段流程

阶段一，clarify：需求澄清。对用户的模糊想法进行多角度追问，确认真正要解决的问题、核心用户场景和最小功能范围，产出 features.md。

阶段二，design：架构设计。选择大、中、小方案，确定分层、模块、数据流、接口和任务依赖，产出 architecture.md 和 tasks.json。

阶段三，review：架构审查。使用五层架构裂隙分析检查数据流、失败模式、状态切换、分层和运维隐患。重大结构问题必须回到设计阶段。

阶段四，build：任务审查与逐模块实现。先审查任务依赖和可执行性，再按模块逐任务实现。每个任务走 TDD，完成后进行零件级小审。

阶段五，module_review：模块基础审查。当前模块完成后，固定检查六个基础审查轴：正确性、测试与验证、安全、可维护性、性能与成本、接口契约。

阶段六，system_review：Agent 系统审查。全部模块通过中审后，固定检查六个一级维度：LLM、上下文工程、工具、约束、验证、纠正。成本、记忆、可靠性和评估作为二级检查项挂载其中。

阶段七，done：归档。确认必须改问题清零、核心路径和关键失败路径已经验证，输出时间线、审查产物和后续运行建议。

## 审查协议 5.1

这次升级前，锻造的中审主要关注模块协作、I/O、分层和测试；大审则把功能、契约、测试、数据流和多种 Agent 维度混在一起，容易重复，也容易依赖审查者临场发挥。

5.1 版本把三种审查明确分层：

模块基础审查负责单模块质量，使用六轴清单；Agent 系统审查负责跨模块闭环，使用六个固定一级维度；架构审查负责寻找系统设计没有覆盖的结构性裂隙。

每个审查轴都必须给出检查对象和依据。没有实际数据时，只能标记为风险推测或待验证，不能编造 Token、性能、成本和稳定性结论。

每个问题都有唯一主归类：单模块问题归 module_review，跨模块协作问题归 system_review，系统边界和长期运行问题归 architecture_gap。其他相关维度只引用问题编号，避免同一个问题被重复报告。

结构性问题不能只写“建议重构”。必须进一步说明根因、影响、目标结构、迁移步骤和验证方式。

## 三个设计原则

第一，裁判不能是运动员。

审查 Agent 使用干净上下文，只读取 brief、指定输入文件和审查标准，不继承设计过程中的争论。这样可以减少 Agent 为自己的设计合理化的偏差。

第二，审查需要收敛判据。

审查不是无限循环。必须改项清零、建议改项不再增长、没有新的严重担忧时，才算收敛；超过上限则暂停并要求人工介入。

第三，审查标准要分层。

基础代码问题、Agent 系统问题和架构结构问题不能混成一张清单。维度越多不代表审查越强，边界清楚、证据充分、问题能够指导修改，才是有效审查。

## 双平台支持

Codex 版使用 `.codex/skills/` 中的技能和内部子 Agent 调度机制。

Hermes 版使用 `forge-hermes`、`forge-product-reviewer` 和 `forge-implementer` 技能，通过 `delegate_task` 派发独立子 Agent。

两个平台共用 CORE.md 的流程和审查标准，平台技能只保留各自的调用方式。

## 当前状态

审查协议已升级至 5.1.0。Hermes 版正式升级已写入 `forge-hermes` 仓库，包含模块六轴审查、系统六维度、证据门槛、主归类、结构性问题重构方案和报告自检。
